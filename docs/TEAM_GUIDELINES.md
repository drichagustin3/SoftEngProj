## 1. Team Working Agreement

The following rules and agreements will guide the team throughout the development of the HOPE Inc. ERP system.

### 1.1 Communication
- All members must communicate through the group's agreed communication channel.
- Members must provide regular updates about their assigned tasks.
- Any problems or delays must be reported to the Scrum Master.
- Members should respond to questions and concerns from teammates.

### 1.2 Task Management
- Every member must follow their assigned tasks and deadlines.
- Tasks must be updated on the GitHub Project board.
- Members should coordinate with the Scrum Master before taking on additional tasks.
- Unfinished tasks must be reported with their current progress and blockers.

### 1.3 GitHub Collaboration
- Developers must work on their assigned feature branches.
- Direct commits to the main branch are not allowed.
- All code changes must be submitted through Pull Requests.
- Code changes must be reviewed before merging.
- Commit messages should clearly describe the changes made.

### 1.4 Professional Conduct
- Respect everyone's opinions and suggestions.
- Help teammates when they encounter difficulties.
- Complete assigned responsibilities on time.
- Maintain a cooperative and respectful working environment.

## 2. Definition of Done (DoD)

A task can only be considered completed when it meets the following conditions:

- [ ] The assigned functionality has been successfully implemented.
- [ ] The code follows the project's coding standards.
- [ ] The functionality has been tested and works as expected.
- [ ] No critical errors or unresolved bugs remain.
- [ ] Database operations work correctly, when applicable.
- [ ] The task meets all its acceptance criteria.
- [ ] Changes have been submitted through a Pull Request.
- [ ] The Pull Request has been reviewed and approved.
- [ ] Changes have been successfully merged into the development branch.
- [ ] The GitHub Project board has been updated to Done.

## 3. Team Role Guide

### 3.1 Scrum Master
- Organizes and monitors sprint activities.
- Maintains the GitHub Project board.
- Ensures tasks have acceptance criteria.
- Monitors deadlines and team progress.
- Helps resolve issues and impediments.
- Conducts sprint reviews and retrospectives.

### 3.2 Developer
- Develops the website and its functionalities.
- Implements frontend and backend features.
- Connects the application to the database.
- Fixes programming errors.
- Submits Pull Requests for completed work.

### 3.3 Database Administrator
- Manages the database structure.
- Prepares and executes database migrations.
- Maintains database relationships and constraints.
- Prepares necessary sample and initial data.
- Ensures database operations work correctly.

### 3.4 Tester
- Prepares test cases and acceptance criteria.
- Tests the functionality of the website.
- Identifies and documents bugs.
- Performs regression and integration testing.
- Verifies that reported issues have been fixed.

### 3.5 UI/UX Designer
- Creates website wireframes and mockups.
- Establishes colors, typography, and design components.
- Ensures consistent website layouts.
- Coordinates with developers during implementation.
- Reviews the usability of completed screens.

## 5. Conflict Resolution & Accountability
- **Blockers:** Raise blockers immediately in the team chat or tag the Scrum Master during standups.
- **Disagreements:** Technical or design disagreements should be resolved via a quick team call or discussion thread; if consensus isn't reached, the Scrum Master helps arbitrate based on the Student Guide.
- **Accountability:** Team members are responsible for updating their task status on the GitHub Project board.
